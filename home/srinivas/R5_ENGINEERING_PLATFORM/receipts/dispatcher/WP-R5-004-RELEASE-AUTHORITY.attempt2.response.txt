WP-R5-004-RELEASE-AUTHORITY is implemented and ready for Codex review. I'm not claiming it qualified or ready. All 345 tests pass across the new, integration, OS-isolation, harness and director-fix suites. The integration suite alone was 142 passed before my changes.

**What changed**
- **`harness/real_approval.py` (new):** holds the fixed store path, the strict schema check and the host reader. The reader refuses any store that is missing, empty, a symlink, or group/world-writable. It also refuses a store that sits inside the harness, snapshot or output directory, or that is one of the caller's own files. Nothing here reads config, environment or CLI input.
- **`release_record.py`:** the REAL scope is now authorized only by an exact matching entry in the store. A caller-supplied REAL `trusted_issuers` entry is ignored. The embedded REAL pin is no longer consulted.
- **`curated_launcher.py`:** for the REAL classification it loads the store after the record's structural and scope checks, and before any artifact is opened. It then mounts the store as an individual read-only file, `real_approvals.json`. The config keys are unchanged, and synthetic runs never touch the store path.
- **`curated_target.py`:** the child re-validates the approval from that mounted file. It takes the file's sha256 and label from the host OS witness, and only cross-checks the launcher bundle's claim.
- **V1 and untouched modules:** `require_real_run_release` still refuses unconditionally. `wp004_train_harness.py`, `os_isolation*.py` and `curated_artifact.py` are unchanged.

**Store schema**
Each approval entry binds the record SHA, issuer, REAL scope, execution id, provenance approval id and provenance receipt SHA. The receipt SHA is typed in by the Director after the external receipt exists. A value equal to the record or authorization hash is refused as self-derived. The schema and the commissioning order (code freeze, then record, then approval, with no source edits afterward) are in the receipt.

**Tests (22 new in `harness_tests/test_real_authority.py`, synthetic bytes only)**
- **Rejections before any artifact open:** a missing or malformed store, caller self-registration of a REAL issuer, and mismatches on issuer, execution, provenance, record, code pins and input pins.
- **Mechanical pass:** a valid fixture approval passes host validation and runs in a real bwrap sandbox. This used synthetic bytes labeled with the real classification, with the store path monkeypatched in the tests only.
- **Child substitution:** the child rejects a substituted store, a tampered bundle claim, a wrong label, and a store modified after the host read.
- **Code hash stability:** the harness tree hash is the same before and after generating the approval store.

**Limitations**
- The production store `authority/wp004_real_approvals.json` and its directory were not created.
- The code cannot authenticate the provenance receipt. It only checks that the Director-entered hash matches the authorization and isn't self-derived.
- Write protection of the store depends on the Director's file permissions.
- `mutation_*.py` was not rerun, and the accepted integration reports were not regenerated.
- Existing tests were not edited. I had to make the launcher pass `approval_store` only for the REAL classification, so an existing test that monkeypatches `validate_release_record` keeps working.

The harness tree hash changed from `92614c60…` to `c50061d7…` because of the new module and three edited files. The snapshot hash is unchanged.
