### Concrete Findings

#### FINDING-01: Grid Post-Cutoff Causal Leakage via Unsorted Availability Buffering

* **Severity:** Medium


* **Trigger:** An unsorted grid feed containing a pre-cutoff timestamp positioned after a post-cutoff timestamp.


* **Consequence:** In `load_curated_grid`, when `availability > cutoff_utc` is encountered, the loader increments `discarded += 1` and executes `continue`. If subsequent rows in the CSV have timestamps earlier than `cutoff_utc`, they are appended to `rows` out of causal sequence. Although line 393 checks `availability <= previous` to catch non-increasing timestamps, the cutoff discard loop should strictly disallow any subsequent rows from re-entering the causal frame.


* **Location:** `source/curated_artifact.py`, lines 403–406:


```python
0403:             if availability > cutoff_utc:
0404:                 discarded += 1
0405:                 continue
0406:             rows.append({"timestamp": availability, "close": row["close"]})

```


* **Minimal Correction:** Enforce a latch once the cutoff boundary is crossed:
```python
if availability > cutoff_utc:
    cutoff_reached = True
    discarded += 1
    continue
if cutoff_reached:
    raise h.ChronologyError(f"{name}: causal row after post-cutoff discard")
rows.append({"timestamp": availability, "close": row["close"]})

```

#### FINDING-02: Target Execution Namespace Drift via `runpy.run_path`

* **Severity:** Low


* **Trigger:** Target modules that depend on global runtime environment adjustments or standard `sys.argv[0]` path resolution.


* **Consequence:** In `os_isolation_bootstrap.py`, the target script is executed using `runpy.run_path(target, run_name="__main__")`. Running as `run_path` rather than invoking a clean subprocess or resetting process-level attributes leaves the bootstrap module cache and caller globals resident in memory.


* **Location:** `source/os_isolation_bootstrap.py`, line 71:


```python
0071:         runpy.run_path(target, run_name="__main__")

```


* **Minimal Correction:** Purge unneeded bootstrap symbols from `sys.modules` or explicitly run inside an isolated module dictionary.
