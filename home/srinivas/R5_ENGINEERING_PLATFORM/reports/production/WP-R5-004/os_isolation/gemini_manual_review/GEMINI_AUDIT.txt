DETAILED TECHNICAL AUDIT
Check 1: BoundedLineReader Physical Read Bounding
Verdict: PASS WITH FINDINGS

1.1 Invariant Verification
Clamping Logic (wp004_train_harness.py, lines 0293–0320):

Every physical read request size is governed by _next_read_size():

limit=min(chunk_size,plan_left,cap_left)
Line 0313 iterates over (plan_left, cap_left) and clamps limit = min(limit, bound). If limit <= 0, it raises ReadBoundaryError before requesting bytes from _handle.read().

Non-Divisible Cap Handling (wp004_train_harness.py, line 0315, 0336, 0348–0350):

If max_physical_bytes is not a multiple of chunk_size, cap_left = self.max_physical_bytes - self.physical_bytes_read forces limit to the exact remaining byte count. Lines 0338–0339 check if read() returned more than limit, and lines 0349–0350 confirm post-read accounting.

Interval Seeks & Straddle Prevention (wp004_train_harness.py, lines 0299–0311):

Interval transitions advance self._pos via _handle.seek(start) (line 0308). If self._buffer retains bytes across an authorized interval boundary, line 0305 immediately raises ReadBoundaryError("line straddles an authorized interval boundary").

Exact Plan Consumption Check (wp004_train_harness.py, lines 0386–0391):

record() asserts self.physical_bytes_read == planned == self.consumed_bytes.

1.2 Identified Finding
Finding F-01 (Severity: MEDIUM): Unplanned Bounded Fallback Path in _reader_for

Trigger: Calling load_stock_block_bounded with file_plan=None (wp004_train_harness.py, lines 0449–0450).

Evidence: In _reader_for (wp004_train_harness.py, line 0450), when file_plan is None, BoundedLineReader(path, chunk_size=chunk_size, max_physical_bytes=max_physical_bytes) is returned without intervals or expected_commitment.

Consequence: In unplanned mode (synthetic testing), the reader relies on load_stock_block_bounded searching for a sentinel row (wp004_train_harness.py, line 0522). If max_physical_bytes is unset (None), reading continues sequentially through warmup, target, and sentinel, leaving physical overread into _buffer unconstrained up to chunk_size - 1 (overread check line 0378 permits 0 <= overread < self.chunk_size).

Minimal Correction: Prohibit execution when file_plan is None if real_execution is True (enforced at lines 0938–0939 and 1042–1043). For testing, require max_physical_bytes to be non-None whenever intervals is omitted.

Check 2: OS-Level Isolation Boundary (bwrap, Bootstrap & Witness)
Verdict: PASS WITH FINDINGS

2.1 Boundary & Kernel Security Controls
Namespace Confinement (os_isolation.py, lines 0343–0346):

The command arguments strictly require --unshare-user, --unshare-pid, --unshare-net, --unshare-ipc, --unshare-uts, --unshare-cgroup, --disable-userns, --cap-drop ALL, --new-session, --die-with-parent, --clearenv, and --remount-ro /.

Filesystem & Mount Exposure (os_isolation.py, lines 0278–0337, 0385–0395):

Starts from an empty tmpfs root (/). All host broad paths (/home, /root, /etc, /usr, /var, project directories) are in BROAD_DENY (lines 0061–0063). Runtime environments are mounted strictly as read-only directories (dirs) and individual shared library files (libs, lines 0282–0283). Input files are bound as individual files under /in/<alias> (line 0326). Only /out is bound writable (lines 0327–0337, 0392–0393).

Live In-Kernel Verification (os_isolation_bootstrap.py, lines 0027–0065; os_isolation.py, lines 0429–0483):

Bootstrap re-probes /proc/self/ns, /proc/self/mountinfo, /proc/self/status (CapEff == 0, NoNewPrivs == 1), /proc/net/dev (ifaces == ['lo'] or empty), /proc/self/fd (no leaked descriptors > 2), and tree/file SHA-256 hashes of /code and /in before executing the target (lines 0048–0063).

Dual-Sided Handshake Nonce (os_isolation.py, lines 0569, 0635–0646; os_isolation_bootstrap.py, lines 0030–0041):

The host launcher reads bwrap namespace IDs via --info-fd (line 0591), matches them against the child's @@WP004_READY announcement (lines 0602–0610), verifies host /proc/<pid>/mountinfo (lines 0613–0619), and passes a secure cryptographic nonce via stdin that cannot be replayed.
