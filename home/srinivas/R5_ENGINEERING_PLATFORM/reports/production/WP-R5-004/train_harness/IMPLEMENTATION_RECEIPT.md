## Director findings → fixes
1. **Exact physical read cap.** `BoundedLineReader` now validates `chunk_size`/`max_physical_bytes` as positive non-bool ints before opening, and each read requests `min(chunk, interval remaining, cap remaining)`; at 0 it raises before issuing any read. `physical_bytes_read` can never exceed the cap even when the cap is not a chunk multiple (tests: caps 105/100/64/63/1/65/257/11 with chunks 64/100/4096 against an independent FileIO witness that logs every `read(n)`: bytes read == cap exactly, no read issued after the failure, repeated attempts beyond the cap issue zero reads).
2. **Per-file read authorization.** New `validate_real_authorization` (pure; opens no data). Exact-key schema binds: authorization SHA (external pin), contract id + contract-file sha, classification, snapshot/protocol/params pins and HEAD, manifest/data/grid/output roots and output dir, Stage B Block 1 sessions, unchanged development risk scope, CNC `DISABLED`, pretrain policy, commitment scope, and per file: canonical path, exact byte intervals, physical byte limit (= interval total), content commitment, provenance id, external boundary evidence, boundary-row authorization. Nothing is inferred from size, timestamp counts or old whole seals. `make_prepare` now does a full PREFLIGHT (stock metadata/paths/sizes, grid manifest, feed SHAs/paths, plan↔metadata bijection, sizes, evidence size) before the first data open. Reads are limited to the plan (seek only between authorized intervals; plan exhausted ⇒ fail closed), the plan must be consumed exactly (physical == consumed == planned), the commitment is verified on the consumed bytes, and `Tripwire(planned_paths=…)` trips on any harness open outside the plan. Validated before any open: wrong/unknown/missing key, any pin/root/session/scope mismatch, wrong-root files, bypass-style extra keys.
3. **preTRAIN vs TRAIN.** Interval kinds `HEADER` / `TRAIN_DATA` / `PRETRAIN_WARMUP_NO_FIT`; default `pretrain_policy=REJECT` (a preTRAIN-dated row, or a mislabelled interval, raises `PreTrainSelectionError`; preTRAIN intervals are refused by the authorization unless `WARMUP_PROVENANCE_NO_FIT`, stock only, warmup only, never grid, never target/sentinel). Audit reports `pretrain_rows_consumed`, `warmup_rows_dated_before_train_start` and a `train_scope` disclosure: retained rows are TRAIN-dated *by timestamp filter only*; physical bytes are classified solely by the authorized interval kind. The stock sentinel and grid cutoff-detecting row must be explicitly authorized (`terminal_boundary_row_authorized`), are disclosed (`boundary_row_authorized`, `boundary_rows_parsed_and_discarded`, `boundary_row_affects_retained_feed=false`) and are never retained. The first-row/manifest `first_timestamp` check applies only when nothing was skipped after the header. The harness exposes no function that generates boundary evidence; the required external schema is `REQUIRED_EXTERNAL_BOUNDARY_EVIDENCE_SCHEMA` and `REQUIRED_EXTERNAL_INPUT_SCHEMA.md`.
4. **No overclaim of IO isolation.** `os_isolation_witness()` is a code gate that always raises `IsolationGateError`; it is not a JSON field and extra keys refuse. The receipt states "python_tripwire_limits: in-process patches only; do not prove native/system IO restriction". The runner refuses even for a fully valid authorization (tested; no data opened).
